# ADR-084 — A duplex wire the platform's own tools can embed (link stub)

**Authoritative copy:** [`exeris-kernel/docs/adr/ADR-084-websocket-provider-spi.md`](https://github.com/exeris-systems/exeris-kernel/blob/main/docs/adr/ADR-084-websocket-provider-spi.md)

ADR-084 is a **cross-repo** decision owned by `exeris-kernel`, shipped in kernel v0.12.0. It gives the kernel a WebSocket SPI — provider, engine, exchange, session and config in SPI, an RFC 6455 frame codec in Core, a Community transport binding, and `AbstractWebSocketExchangeTck` as the merge gate.

## Why this stub exists — the SDK gains a surface

Same shape as [ADR-043](ADR-043.link.md): the kernel gained a primitive, and the SDK's job is the design-time expression of it. The SDK-side decision is **not** taken here — it is [ADR-072](ADR-072-kernel-preview-spi-reserved-surface.md)'s 2026-09-03 amendment (obligations 16–24), which adds `@Channel` as a fourth reserved surface on the same three-part test that admitted `@Blob`, `@Schedule` and `@RouteAccess`. This stub is the awareness anchor, not the design.

| | |
|:---|:---|
| Annotation | `@Channel(messageType, subprotocol)`, `@Target(TYPE)`, beside `@ExerisDomain` |
| AST carrier | `DomainMetadata.channel` → `ChannelMetadata` (trailing, nullable) |
| Status | **RESERVED** — no processor extracts it, no generator opens an endpoint, `-io` does not read it |
| 1.0.0 freeze | **excluded**, until the kernel promotes `…spi.websocket` out of `preview` *and* the tooling transcription exists |

## What the SDK owns, and what it deliberately does not

The SDK expresses **that an entity has a duplex channel**, and nothing about how one is operated. The message-size limit is a kernel configuration path (ADR-071), the origin allowlist is a deployment's fail-closed security posture, the frame format is not a choice the kernel offers, and reconnection is the consumer's to build — each is argued in ADR-072 obligation 20 and stated on the annotation itself.

The distinction that justifies a new annotation rather than a flag: `@ExerisDomain.realTimeApi` and `@Action.streaming` are SSE, **one-directional by construction**. ADR-084 §2 keeps the duplex exchange a sibling of `HttpStreamExchange` for the same reason ADR-043 gave — a mode flag conditions an invariant that is currently unconditional — and the SDK mirrors that split rather than overloading the streaming attributes.

## The `preview` tier, read precisely

ADR-084 §10 ships the SPI `preview` **by decision**, gated on benchmark evidence a TCK structurally cannot supply: concurrent connection count, frame throughput, backpressure under a slow reader, teardown of a dead peer. What is unproven is **durability under load, not the shape of the contract**. That is why a design-time carrier can be built against it now while still being excluded from the 1.0.0 freeze — ADR-072's stability-ordering rule forbids *freezing* an SDK annotation over a preview SPI, not shaping one.

## The consumer

`exeris-platform`'s Studio and CMS wiring. ADR-084's own named consumers are Platform LSP and Studio; the LSP half is transport (LSP JSON-RPC over a socket, needing no annotation), and the Studio/CMS half is the one that reaches a domain declaration. The CMS content types are `@ExerisDomain` declarations today — `studio/docs/cms-strategy.md` §4, presently "documentation as code" that "doesn't compile against any current Exeris SDK" — and §7's migration to Platform v1.0 lists real-time editing among what it brings. `exeris-platform`'s own [ADR-084 stub](https://github.com/exeris-systems/exeris-platform/blob/main/docs/adr/ADR-084.link.md) records the transport half and its `preview` exposure.

## When to consult ADR-084 from exeris-sdk

- Before adding any attribute to `@Channel` — the four exclusions above are decisions, not omissions.
- Before promoting the surface out of reservation: check whether the kernel has moved `…spi.websocket` out of `preview`, and whether the `exeris-tooling` slice exists.
- Before adding a per-action duplex declaration — see ADR-072 obligation 18, and `@Action.realTimeUpdates`, which already occupies that space unreserved.
