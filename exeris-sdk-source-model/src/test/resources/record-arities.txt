# Record-constructor ledger — the record-growth stance (MIGRATION-0.x-to-1.0.md §3).
#
# One line per public record on the wire-carrying surface: every constructor arity the
# record has published, ascending. RecordConstructorLedgerTest asserts that for each arity N
# a public constructor still exists whose parameter types are the record's first N component
# types, and that the record's current canonical arity is on the line.
#
# APPEND-ONLY. When a record grows, append its new arity in the same commit and keep the old
# constructor as one that delegates with null for the new trailing components — that is what
# lets code compiled against the previous release keep linking and keep compiling. Deleting an
# arity together with its constructor is the one edit the test cannot see; japicmp's strict
# CONSTRUCTOR_REMOVED reports it under -Psemver, and review catches it wherever that does not
# run.
#
# A major re-baselines. 1.0.0 removes DomainMetadata.tenantScoped and DomainMetadata.apiVersion
# from the middle of the record, which changes every DomainMetadata constructor at once; its
# line restarts from the 1.0.0 shape then, and only then.
#
# Earlier arities recorded here, and the release whose shape each one preserves:
#   ActionMetadata=17            0.11.0 (routeAccess added in 0.12.0)
#   DomainMetadata=39            0.11.0 (routeAccess, channel added in 0.12.0)
#   SystemFieldsMetadata=10      0.11.0 (sharedScopeField added in 0.12.0)
#   SagaMetadata=16              0.12.0 (six compensation components added in 0.13.0)
#   DomainEventMetadata=4,6      pre-EV1 and pre-EV2 (payload lists, then the trigger triple)
